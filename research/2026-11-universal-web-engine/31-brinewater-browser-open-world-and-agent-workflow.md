## 這是什麼？為何值得關心？

Brinewater 是創作者於社群介紹的「以美國聖路易真實街道為背景、可在瀏覽器遊玩的 GTA 類型開放世界」案例。它的研究價值不只是交通或角色系統，而是**如何利用真實地圖生成大型場景、拆解代理開發工作包、從實際畫面而非僅從測試綠燈判斷品質**。因未取得可審計的公開程式碼，本文將作品敘述與可遷移的工程建議嚴格分開。

## 2｜技術拆解：開放世界不是一張超大的網格

下表是由需求導出的**通用可行架構**，不是聲稱 Brinewater 一定採用。

| 系統 | 建議技術分層 | 核心驗收 |
| --- | --- | --- |
| 地理來源 | OSM 道路／建物資料 + 明確座標系 + 資料版本固定 | 路口連通、坐標一致、來源/衍生資料授權 |
| 地圖切塊 | Spatial chunks、quadtree／grid、視野載入與卸載 | 移動速度上升時無空白區與記憶體增長 |
| 交通路網 | Road graph + intersections + lanes + traffic signals | 車流不陷入死結、離開視野可低頻更新 |
| 物理與渲染 | 分離固定步進 simulation / variable render；近距離碰撞 | 調低畫質後不改變物理結果 |
| NPC | 遠近分級：活動代理、簡化狀態、休眠 | 視野切換不會突然消失／破壞任務 |
| 資產 | Instancing、LOD、texture atlas／KTX2 候選 | GPU memory、draw calls、mesh disposal |
| 任務／職業 | 命令與事件系統、資料驅動任務狀態 | 保存／恢復、不可重入與事件去重 |
| 遊戲偵錯 | Deterministic seed、replay/input trace、定點截圖 | 同路段多次重現相同 bug |

把「地圖生成」與「可玩世界」分開是關鍵：道路和建物可能能從開放資料繪出，但導航網格、碰撞、路口規則、人物動畫、任務狀態等都需要另外處理。地圖來源也要遵守 ODbL／資料集實際條款與署名要求，不能只看下載是否免費。

## 3｜創作者描述的 Agent 工作流程（僅作者自述）

社群摘要稱作者以 Opus 承接系統設計、跨模組審查與工作規格，再分派 Sonnet 在不同 Git worktrees 處理界線清楚的功能；長期知識存入文件，並用 headless browser 操作遊戲、觀察畫面與截圖。

**可遷移的工程原則**（本研究建議，不是把作者方法視為已被證明最優）：

1. **主控切割邊界：**任務契約列出檔案所有權、輸入/輸出 API、測試、不能變動的路徑；避免多個 Agent 改同一座標系或同一場景狀態。
2. **Worktree 隔離：**每個工作包獨立工作樹／分支，合併前檢查 shared types、事件 schema、遊戲迴圈與資源釋放。
3. **雙重驗收：**單元／整合測試確認功能不回歸；瀏覽器實際跑角色移動、開車、停車、快速轉鏡頭並擷取畫面，確認場景真的如預期。
4. **視覺可重現：**同一個 seed、輸入腳本、camera、時間、天氣、畫質、裝置與 viewport 對照新舊截圖；另記錄 FPS p95、主執行緒長任務、draw calls。
5. **失敗阻斷：**若變更導致畫面退化、性能未達門檻或 source 變更超出授權，不能因 CI 綠燈而直接宣稱完成。

## 4｜驗證／對照實驗（未執行）

| Case | 操作腳本 | 驗收輸出 |
| --- | --- | --- |
| B1 World streaming | 持續跨越 20 個 chunk、轉向／折返 | 加載延遲、卡頓、資產回收、空白地圖 |
| B2 Traffic | 車流穿越 5 個號誌路口 | 死結、碰撞、平均 CPU update time |
| B3 Gameplay | 上下車、與 NPC 互動、切換鏡頭 | input 狀態、角色穿模、任務一致性 |
| B4 Agent QA | 同一 bug 在兩個 branch 以固定 seed replay | 修復結果與副作用的可重現證據 |
| B5 Device | 桌面、Android 真機、GPU 弱化回退 | 可玩性、穩定性、p95 frame time |

上述步驟可作為任何瀏覽器 3D 專案的測試規格；不代表本次已經在 Brinewater 執行。

## 5｜授權、風險與採用結論

- **原始碼：**未查到能核對並歸屬於此作品的官方開源儲存庫；不得猜測 repo 或抄寫逆向程式碼。
- **地理資料：**OSM、政府資料、商用瓦片 API、模型素材可能有不同授權與歸屬，導入前逐項建立來源台帳。
- **模型歸因：**「全程由 Claude Code 撰碼」是創作者自述；人類決策、提示詞、除錯與資產挑選同樣是開發工作，不能把自述推成零人力工程成本。
- **候選採用：**研究可重現的瀏覽器視覺 QA、工作樹隔離與大世界 LOD；是否採用取決於自己的瓶頸資料。
- **決策狀態：**研究候選，未批准新增依賴、修改遊戲或部署。
