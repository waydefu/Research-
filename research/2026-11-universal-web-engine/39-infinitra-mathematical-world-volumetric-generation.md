# INFINITRA：以連續數學世界、體積生成與可持久化修改設計大型探索空間

**來源最後核對：2026-11-07（Asia/Taipei）**  
**上游：** [Richard Bogad／INFINITRA](https://github.com/richardbogad/INFINITRA)，2026-10-31 初始提交 `c43ddb147191d452eb2905572397409be92cce60`。本次閱讀 README、LICENSE.md、EULA.md 與專案中的權利聲明；未取得可驗證的核心生成演算法原始碼、未安裝或執行遊戲。  
**研究範圍：** 程序化世界／體積式生成／決定性內容／無縫細節層級／修改持久化／PC VR／授權邊界。

## 1｜作品定位

INFINITRA 是 Windows／PC VR 的 Early Access 探索世界。作者將其描述為「由一個連續數學定義生成，按位置和可見細節需求計算」的三維世界，聲稱尺度達**十兆公里（10 trillion km）**。遊戲提供離線、無帳號探索；角色、物品、多人共享修改和地點儲存等部分功能需帳號及月費方案。

它提供一個值得研究的**架構命題**：不要把所有地點預先烘焙成巨大地圖檔，而是從相同規則與座標產生相同世界內容，僅儲存玩家造成的差異。但「連續」「十兆公里」「無接縫」是**上游敘述**；公開 README 和授權說明不足以獨立確認算法細節、浮點精度與實際運算成本。

## 2｜作者聲稱的技術分層與可推導的工程問題

| 作者描述／公開說明 | 可研究的通用技術方向 | 尚無原始碼／實測的部分 |
| --- | --- | --- |
| 世界是連續數學定義，位置可隨時被求值 | 位置函數、固定種子、階層式決定性生成 | 未公開核心函數、種子管理、版本遷移與跨裝置一致性演算法 |
| 不是只有地形表面，能有洞穴、挑空和室內 | 三維體積／隱式幾何與空間占用描述 | 不能擅稱採用 SDF、Marching Cubes、雙輪廓、Sparse Voxel 或某種特定網格演算法 |
| 走近時生成更多細節，相鄰層級會連續銜接 | View-dependent LOD、幾何過渡、前景快取與排程 | 缺少幾何接縫、重建延遲、p95 影格耗時、遠景精度的獨立測量 |
| 原始世界按數學規則可再次生成，只存玩家變動 | Canonical world seed + delta／事件紀錄、同步與衝突解決 | 多人並發修改、回滾、壓縮、資料庫一致性與版本升級方案未核對 |
| 風與空間幾何影響聲音，支援天空／日夜／雲 | 幾何感知混響、環境音、程序化大氣與光照 | 沒有聲學參數、雲模型、延遲及跨平台 Audio API 的驗證證據 |
| 無接縫探索與自行調整畫質 | 內容串流、計算排程、CPU/GPU 分工、視距與降級策略 | 沒有確切 frame budget、記憶體峰值或低階裝置兼容數據 |

**要避免的錯誤歸因：** 這不是可以直接下載的「完整開源程序世界引擎」，也不能因它有巨型世界就推論已解決無限精度、所有地形物理、任意硬體 60 FPS 或真實多人強一致。

## 3｜玩法與營運限制對技術選型的影響

作者 [README](https://github.com/richardbogad/INFINITRA/blob/main/README.md) 列出雙角色探索、洞穴／建築室內、日夜循環（30 分鐘一日）、空間音效、VR 操作，以及多人模式的共同地形改動。免費訪客能探索世界，但**共用物件、拾取物品、保存多個地點及部分社交能力屬訂閱功能**；不能據此推論整個世界與服務端系統完全免費且可自架。

作者建議硬體為 **Windows 10+、Ryzen 9 7900 或同級、RTX 4060 Ti 或同級、16 GB RAM、3 GB 儲存空間**，VR 為連接 PC 的 OpenXR 頭盔。這是作者建議配置，**不是跑過的最低規格 benchmark**，更不能證明瀏覽器、Android 或低功耗裝置能順利重現。

## 5｜可重現的獨立驗證計畫（全部 NOT RUN）

| 實驗 | 實作方式 | 驗收證據 |
| --- | --- | --- |
| 位置一致性 | 固定規則版本及座標，跨不同裝置／兩次啟動取得相同資料 | 位元級或容許誤差內的特徵／雜湊一致性 |
| LOD 接縫 | 沿層級交界反覆平移／轉向；改變距離及視角 | 明確的 crack/popping 指標、影像差分與時間紀錄 |
| 體積世界 | 在獨立範例中生成洞穴、室內、懸垂地形，與高度圖方案對照 | 幾何完整性、生成時間、儲存量及更新成本 |
| Delta 持久化 | 同一種子先挖洞再存更動／重啟／並發修改 | 更動內容精確回放、版本相容及衝突解決策略 |

**工程採用條件：** 先做與產品無關的最小數學世界原型，對生成可重現性、時間預算、LOD 接縫及修改同步設定可量測門檻。成果若要移至瀏覽器或其他引擎，需重新設計精度、記憶體、GPU 能力和網路行為，不能假設 Unity／Windows 的展示可直接移植。

## 6｜結論

**值得研究其「定義世界而非儲存世界」的理念；不適合作為可直接引用的完整開源演算法或手機效能證明。** 主要知識價值在決定性體積生成、連續多尺度表示與 delta-only persistence 三個方向；關鍵工程性能和演算法細節尚未獨立確認。
