## 2｜應拆的五種設計層（研究方法，非已觀察結果）

### 2.1 首屏視覺層級

分析視覺焦點（建築／環境／人物）、Logo、標題、導航和操作 CTA 的優先順序；記錄桌面與手機的真實排版斷點、主體遮擋、字體最大最小尺寸、明暗對比。若 Hero 使用大型圖片或影片，還要記錄第一幀、poster、預載策略、畫面長寬比與 letterbox/crop。

### 2.2 動態敘事節奏

將整頁按轉場節點而不是卡片數量拆解：引入、主視覺、環境故事、建築特色、位置、行動召喚。對每個節點測試 scroll progress、停留／進退、重新整理、歷史返回、鍵盤與觸控。不能只有漂亮的自動播放影片，還需要用戶能掌控的閱讀節奏。

### 2.3 字體與排版

用字重、字寬、行高、標題背景對比與段落行長建立品牌層級；中文／西文切換時檢查字型回退、全形標點、長標題換行。昂貴字體本身不是高級感保證，重點在可讀性、語意與排版比例。

### 2.4 色彩與攝影語言

先評估圖片或影片的真實品質，再評估全站色彩（深淺／冷暖／材料感）、曝光一致性、遮罩、顆粒、景深與轉場。別拿模糊、不必要的泛光或大面積玻璃質感掩飾低品質素材。

### 2.5 手機與無動效降級

在觸控裝置檢查：點擊區域、底部安全區、橫向溢出、固定導覽遮擋、影片數據量、低功耗模式與 reduced-motion。關閉動畫後主要內容應仍完整可讀，CTA 不應被進場動畫鎖住。

## 3｜待驗證的技術候選，絕不是逆向結果

| 能力需求 | 可研究工具／方式 | 代價與限制 |
| --- | --- | --- |
| Scroll-driven pin／timeline | CSS scroll-driven animations 或 GSAP ScrollTrigger | 瀏覽器相容、同步漂移、過度腳本成本 |
| Smooth scrolling | 原生 scroll first；必要時再評估 Lenis | 會影響錨點、回上頁、輔助技術 |
| 頁面轉場 | View Transitions API／CSS／動畫函式庫 | 前進／返回狀態、過度動態 |
| 互動型 3D | Three.js / WebGL2（只在真的需要時） | GPU、電池、context lost、手機熱負載 |
| 大型媒體 | AVIF/WebP responsive images；影片 poster 與明確載入策略 | 計算 LCP、帶寬與首屏可讀性 |

這是技術選項比較，並**沒有**推定該站使用任何一項。

## 5｜可遷移的一般設計原則

1. **沉浸感來自連續敘事，不是每一個區塊各有一個動畫。** 認清整頁節奏，再決定哪些位置應有場景／圖片轉場。
2. **素材品質優於動效數量。** 先修照片品質、光色、排版和留白，再用有限的動態引導視線。
3. **保留高級感，但不犧牲功能。** 捲動、導航、內容查找、表單與 CTA 必須可用且能跨裝置回退。
4. **先建立畫面證據，再選技術。** 若作品只是由圖片、文字與少量動畫組成，不應為了高級感硬塞 WebGL。
5. **尊重原創與授權。** 原站視覺可作案例分析，不代表可重用第三方攝影、字體、影片、原始碼或品牌元素。
