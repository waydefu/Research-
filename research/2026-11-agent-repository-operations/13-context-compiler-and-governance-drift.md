# 任務上下文編譯、規則漂移與可驗證的代理治理

查核日期：2026-11-24（Asia/Taipei）。證據：公開 PR 描述及可見變更差異；沒有重新執行來源專案測試。本文為通用設計評估，不代表已導入或取得 EAG-100 分數。

## 問題與原理

長期協作的成本並非只有模型 Token，而是規則重複、過期摘要、任務前提缺漏及多宿主不一致。應把規則真值、目前狀態、任務輸入、歷史證據分開。先以任務 ID 取得最小必要資料，再產生可回溯的上下文 capsule，而非要求代理每次閱讀整個儲存庫。

- 根規則保留授權、真值位置、必要閘門及導航；任務專屬流程延遲載入。行數上限是編輯預算，不是安全要求，不得因此刪掉強制控制。
- 多宿主規則採單一真值與可重現衍生檔；檢查生成結果是否漂移。不要手動維護多份等價規則。不同宿主能力仍需獨立測試。
- Compiler 輸入為固定 schema 的任務卡、依賴契約、版本化來源與條件式參考範例；輸出欄位帶來源路徑、版本及缺漏狀態。必填來源失效應拒絕施工，可選資料缺失可降級並標記。
- 起草、事實／契約審查、呈現品質審查可使用不同上下文；審查者仍須接觸原始證據。正向範例是參考而非強制模板，避免固定範式及評測過擬合。
- 交接記錄基準 SHA、未決事項、下一步、真實檢查與回退方式；摘要、工具回傳、PR 文案均不是授權。歷史決策不得覆寫現在狀態。
- 指令守門區分讀取與異動；以宿主權限、隔離與外部核准為主要安全邊界。Regex hook 只能補防，無法證明所有 shell 包裝、別名與間接執行皆受控。

## 評估與採用

| 控制 | 最小證明 |
| --- | --- |
| 上下文編譯 | 多字欄名、缺必填、缺選配、錯誤 ID、來源更新及版本錯配的正負測試 |
| 規則生成 | 生成後零 diff、故意修改鏡像必須失敗，明示宿主差異 |
| 交接 | 過期 SHA 不當作現況；確認工作分支與實際 CI，不依賴摘要 |
| 權限 | 偽造授權、未批准寫入、命令包裝及間接調用的拒絕案例 |
| 成本 | 相同任務比較完整讀檔與 capsule 的 Token、工具呼叫、時間、成功率和漏檢；尚無量測 |

既有治理框架已涵蓋授權、索引與成本；新增價值在於可重現規則生成、任務欄位編譯及負向漂移測試。適合規則多、多人或多代理長期維護的專案；小型專案先採導航和簡單契約即可。沒有同條件測試不宣稱節省比例。
