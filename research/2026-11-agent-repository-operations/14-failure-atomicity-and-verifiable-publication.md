# 可靠交付：原子寫入、程序收尾、同步讀回與故障注入

查核日期：2026-11-24。公開 PR 描述及可見差異的有限審閱；合併狀態不等於生產驗收。未重跑測試或操作外部服務。

## 失敗如何傳播

可靠系統須區分「命令返回」、「內容寫入」、「持久化完成」、「外部服務讀回相符」及「使用者驗收」。上游成功而後段失敗時，不可回傳整體成功。

| 失敗型態 | 設計模式 | 驗收 |
| --- | --- | --- |
| 子程序先退出、輸出仍在管道 | Node.js 等待 close，處理 error、退出碼及訊號，限制輸出緩衝 | 模擬 exit 後仍有 stdout/stderr；非零碼、EPIPE、超限、取消 |
| 檔案覆寫中斷 | 同檔案系統暫存、原子 replace、成功後才更新記憶體；跨磁碟不得假設 rename 原子 | 寫入／replace 故障；舊檔仍在、partial 清理；另測斷電與 fsync |
| 索引損壞 | 先保全原始資料，再允許重建；備份失敗就停止 | 損壞輸入、無權限、磁碟滿、備份恢復 |
| 並行共同編輯 | 樂觀並行控制、revision guard、最小差異更新、無改動零寫入 | 過期 revision 拒絕；Unicode UTF-16 邊界；標題／正文讀回 |
| 發布事件過期 | 同一目標序列化，開始時刷新權威版本；記錄實際 SHA 與回應 | 舊事件晚到、連續推送、重試、部分成功、版本不一致 |
| 長時任務失敗 | 快速探測與長工作分開設定逾時；保存可驗證 checkpoint，支援冪等續跑 | 中途失敗保留完成項、拒絕異種／重複／缺號資料 |

## 安全與操作

- 讀取授權、建立授權、輸出能力各自對應明確的資源操作，不能以近似權限替代。實際註冊路由與契約清單做雙向集合比對，未掛載不當作可使用介面。
- 在資料庫查詢、外部 API 分頁、輸出與日期範圍的入口設上限，避免讀完全部才拒絕；測試上限、上限加一及未寫入。拒絕結果亦須可稽核。
- PowerShell 呼叫原生命令時驗證實際退出碼、版本與讀回結果；清除暫存憑證。禁止以單一 stdout URL 或零退出碼當作部署證明。
- 探測快取可降低頻繁啟動外部程序的成本；TTL 增加會擴大過期窗口。非信任目標與暫時逾時分開處理，敏感異動前需依威脅模型重新驗證；不得因快取而放寬信任。
- 執行期權限 URL、憑證與暫時存取狀態不要當成永久資料保存。來源資產須固定版本、核對 hash、保留完整授權與必要對應原始碼；不把授權證明等同於模型載入成功。

## 採用門檻

先用故障注入與 mock 重現，再做沙盒整合與人工操作；最後才放行生產部署。原子 replace 不保證多檔交易或斷電耐久；真實長時工作與外部服務需另驗。CI 的唯讀權限和取消過時工作適合純檢查，實際發布不能直接套用取消策略。任何外部異動須按授權邊界另行批准。
