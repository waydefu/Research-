# EAG-100｜企業級 AI Agent × GitHub Repository 治理評分規範

**版本：v1.0（2026-11-02）**  
**性質：研究團隊自訂工程評分框架；非 NIST、OWASP、SLSA、GitHub、OpenSSF 的官方評分、認證或合規聲明。**  
**適用對象：** 允許 Coding Agent 讀取、修改、測試或發布程式的 GitHub Repo、組織及其執行環境。由稽核人按實際風險界線界定受評範圍。

> 企業級的定義不是使用最多工具，而是「即使模型判斷錯誤、遭遇提示注入、索引過期、CI 故障或額度耗盡，仍有可強制執行的安全邊界與回退機制」。

## 0. 使用前提與計分規則

- 本量表共 **20 個檢查點，每點 5 分，總計 100 分**；依九個面向分配權重。**每一點只允許 0／2／5 分**：0 = 缺失、未設置或無可採證據；2 = 有部分控制但未經完整驗證；5 = 持續強制執行、已測試且提供近期證據。
- 記錄 `evidence_uri`、證據擷取時間、Repo/branch/commit SHA、稽核者、適用範圍與失敗案例。政策文件和 AI 自我宣告，**不能單獨拿滿分**。
- **不得因「不適用」而直接領取滿分**。如確有不適用，標 `N/A` 並附理由；比較分數使用「已獲分數 / 適用上限 × 100」，**同時揭露原始適用上限**，且不可把缺少證據歸為 N/A。
- **五項 P0 強制閘門優先於分數**。任何適用 P0 未通過、尚未驗證或有未解重大問題 → **不得宣稱企業級上線合格**，即使總分 100。
- 證據過期（例如分支規則、憑證或 CI 改變）需重新稽核；此評分是**時點快照**，不是永久認證。
- 本量表不替代法規合規、威脅建模、安全滲透測試、供應商審查或組織治理要求。

## 一、九大面向與 20 項可驗證控制

| 面向 | 配重 | 控制 ID / 5 分條件 | 強制驗收的證據範例 |
| --- | ---: | --- | --- |
| Agent 權限與執行隔離 | **20** | **A1**：最小權限、角色／工具白名單有實際強制 | 工具權限設定、拒絕案例 |
| | | **A2**：代理運算與敏感環境隔離（檔案／網路／Secrets） | Sandbox 測試、外連拒絕 Log |
| | | **A3**：風險操作在模型之外有批准與執行分離 | 實際被阻擋的合併/部署演練 |
| | | **A4**：受託資訊不可提升權限，具提示注入防護 | 惡意 Issue/PR/MCP 測試 |
| GitHub 與變更治理 | **15** | **G1**：受保護分支與 PR 規則可強制執行 | Rulesets/API 匯出、繞過測試 |
| | | **G2**：CODEOWNERS／審核／關鍵變更雙人或獨立批准 | PR 審批與失效重審紀錄 |
| | | **G3**：Required Status Checks、部署門檻與受保護路徑 | CI 與阻擋案例 |
| 供應鏈與軟體安全 | **10** | **S1**：SCA/SAST/Secrets 掃描、修補窗口與例外追蹤 | 掃描結果、修補時效 |
| | | **S2**：Dependencies/Actions pin、SBOM、可驗證 Build Provenance | Lockfile、SBOM、簽章或 Attestation |
| 測試與品質驗收 | **10** | **T1**：Unit/Integration/E2E/Contract 流程依風險覆蓋 | CI、真實測資與回歸 |
| | | **T2**：Agent 行為、失敗與權限負向案例納入測試 | 代理越權/錯誤恢復測試 |
| 搜尋與索引可信度 | **10** | **I1**：檢索追溯來源與版本（SHA/行號/ACL） | 檢索結果 + 原文核對 |
| | | **I2**：索引 Freshness、Coverage、漏報與失效回退驗證 | stale index、零結果誤判測試 |
| 資料保護與隱私 | **10** | **D1**：Repo/tenant 資料分級與最小可見權限 | ACL 負向測試 |
| | | **D2**：Secrets/PII 的保留、刪除、傳輸與備份控制 | Retention 政策、實際刪除測試 |
| Token 與成本治理 | **10** | **C1**：主代理、子代理、快取、工具、重試的總成本可觀測 | Usage trace、成本/成功任務 |
| | | **C2**：預算／並發／重試上限強制執行且 fail closed | 超額拒絕／停機實測 |
| 可觀測性與稽核 | **10** | **O1**：任務、模型、工具、原始變更與批准可串聯追溯 | Request ID、Trace、Commit |
| | | **O2**：異常告警、證據保存、防篡改與時間同步 | 告警演練／稽核記錄 |
| 事故回復與持續治理 | **5** | **R1**：Kill Switch、Rollback／Restore、事件處理與定期重測 | 演練報告、RTO/RPO、回退證據 |

### 評分細節

- **5 分：** 不只配置了功能，還有近期可重現的正向／負向測試，並證明適用範圍內無輕易繞過。
- **2 分：** 有設置但沒有完整負向測試、部分 Repo 未涵蓋或只有部分證據。
- **0 分：** 未設、不可驗證、已失效、發現可繞過且未修復。
- 若一項控制含多條條件，必須全數滿足才可拿 5 分；不要用工具存在取代控制生效。

## 二、五項 P0：一票否決的強制閘門

| ID | 強制要求 | 最低驗收方式 |
| --- | --- | --- |
| **P0-1** | Agent 不能自行獲得更高權限；Prompt / AGENTS / Skills 不可突破系統權限 | 使用低權限憑證嘗試執行未批准工具／敏感路徑，確認拒絕 |
| **P0-2** | 合併、正式部署、刪除、憑證與權限變更需外部獨立批准；AI 不能自我批准 | 有意模擬不合規 PR／部署，檢查 GitHub／部署平台阻擋 |
| **P0-3** | GitHub Issue、PR、文件、MCP／網頁內容是非可信資料，不能成為指令授權 | 注入惡意內容並檢查不能觸發高權限執行 |
| **P0-4** | 授權、Required Checks、硬預算、安全索引驗證失效時，不得暗中放寬風險控制 | 缺 CI 結果／索引 stale／超出預算的負向測試及 fail closed 證據 |
| **P0-5** | 高風險操作可追溯、可停止並有真實回退能力 | 追溯批准與操作記錄，演練 Restore／Rollback 與 Kill Switch |

**區分：** P0-4 的「失敗即停止」針對安全與資料完整性所需控制；一般輔助搜尋系統故障可在仍守住 ACL 與來源驗證的前提下退回可信原始碼搜尋，並標示結果不完整。

## 三、成熟度級別

| 分數 | 級別 | 意義 |
| --- | --- | --- |
| 0–59 | L1 初期 | 能執行任務，不具備充分治理 |
| 60–74 | L2 基礎 | 基本規則、CI 和角色分工 |
| 75–89 | L3 成熟 | 多數品質／安全控制可測 |
| 90–94 | L4 企業候選 | 可提交正式稽核；**仍須 P0 全部 PASS** |
| 95–99 | L5 高成熟度 | 持續驗證、事故演練、成本治理 |
| 100 | L5 滿分 | 20 項控制全部有充分當期證據，且 **P0 全 PASS** |

**上線宣告：** 分數 ≥ 90、全部適用 P0 已 PASS、無未解的重大已知風險，才可依本研究框架稱「EAG-100 企業級治理合格（自訂標準）」。低於 90 或 P0 未達標，即使自稱 Enterprise 也不可通過此量表。

## 四、使用方法（不會自動部署）

1. 確認稽核的 Repo、分支、CI、Agents、工具和生產環境範圍。
2. 以[稽核模板](EAG-100-AUDIT-TEMPLATE.md)逐項填證據，未知給 0 或 Unknown，不亂猜。
3. 先檢查五個 P0，若失敗立即標記 **NOT QUALIFIED**，但仍可繼續評分作改善分析。
4. 逐項計分與保留 Evidence URL；計算總分與適用上限。
5. 提出修復順序：P0 → 權限 → 供應鏈 → CI → 搜尋新鮮度 → 成本／觀測。
6. 修正後再次執行負向測試；保留前後差異、負責人與稽核日期。

## 五、標準來源與對照邊界

- [NIST SP 800-218 SSDF v1.1（Final）](https://csrc.nist.gov/pubs/sp/800/218/final)：安全軟體開發生命週期；**Rev.1 / v1.2 在 2026-11-02 仍列為 Draft**，不能誤當 Final。
- [NIST SSDF Publications](https://csrc.nist.gov/projects/ssdf/publications)：版本狀態。
- [SLSA v1.2 Specification（Approved）](https://slsa.dev/spec/v1.2/)：供應鏈 Source / Build Track、來源與建置 Provenance；不等於 Agent Runtime 沙盒認證。
- [OWASP Agent Control Standard（ACS）](https://genai.owasp.org/resource/agent-control-standard-acs/)：代理可觀測與 runtime 控制 Hook 的開放標準方向；不是 EAG-100 官方分數表。
- [OWASP Agentic Security Initiative](https://genai.owasp.org/initiatives/agentic-security-initiative/)：AI Agent 風險分類與研究。
- [GitHub Rulesets 官方文件](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/managing-rulesets/available-rules-for-rulesets)：PR 審核、Required Checks、簽署提交、保護規則等具體控制。
- [OpenSSF Scorecard](https://github.com/ossf/scorecard)：開源專案安全檢查**不等於** EAG-100 或企業級認證。

## 六、已知界線

本研究只是**量表設計已完成**，尚未對 `Research-`、`delta` 或其他 Repo 進行現況正式稽核，不包含分支規則、CI、Secrets、帳號權限的實際檢查；**絕不可宣稱其已得到 90/100 或 100/100**。
