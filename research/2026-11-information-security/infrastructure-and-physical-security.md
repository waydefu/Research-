# 資訊基礎設施、實體安全與復原能力

> **研究範圍：**機房、人員、設備、資料備份、異地備援與媒體安全管理。 資料溯源見 [SOURCES](SOURCES.md)。


## 資訊中心與實體安全

資訊中心須提供穩定的資訊服務；**Physical Security（實體安全）**保護機房設備及外部環境，不僅是網路攻防。（PDF 第 2 頁）

## 人員與組織（第 3–16 頁）

原始資料討論資安維護計畫、人力與經費、資安政策、核心系統／資產盤點、風險評估、事件通報與演練、委外管理及持續改善；並列舉不同類別的資安專業證照，例如管理、供應鏈、網路、應用程式、資料庫、雲端及無線網路安全。

**注意：**原始資料引用的我國資安法令與機構職責，屬原始資料當時內容；具體法定義務與組織適用範圍需另行核對最新法律版本。

## 機房環境安全（第 17–20 頁）

| 風險 | 原始資料提出的保護方向 |
| --- | --- |
| 溫度、濕度、落塵 | 維持設備可接受的運作條件、清潔及空氣品質 |
| 停電 | **UPS（不斷電系統）**、供電備援或妥善關機 |
| 機房位置／靜電 | 避免電磁干擾、處理靜電與位置風險 |
| 火災／雷擊 | 防火措施、合適的消防設計、接地與防雷 |
| 地震／水災 | 固定設備、災防與復原規劃 |

原始資料舉機房溫度 20–25°C、濕度 40–60% 為示例；**這不是所有設備通用的最新機房標準**，真實設計應依設備規格與現行工程準則評估。

## 硬體與網路（第 21–27 頁）

- 電腦系統故障屬於系統的 **Availability（可用性）** 問題。
- **Fault Tolerance（容錯）**：設計備援能力，使單一設備故障時仍可繼續作業。
- 網路連線與品質應監測；原始資料舉 **ping** 作為連線檢測例子。
- **注意：**ping 不通並不必然等於主機故障，可能是網路設定、防火牆或 ICMP 策略因素（整理補充）。

## 軟體、備份、異地備援（第 28–37 頁）

軟體管理：控管作業系統及工具的權限、更新與系統資源使用情況。

### 三種備份差異

| 備份 | 每次備什麼 | 還原時通常需要 |
| --- | --- | --- |
| **Full** 完整 | 所有選定的資料 | 完整備份 |
| **Differential** 差異 | 自上次**完整備份**之後的變更 | 完整備份＋最新差異備份 |
| **Incremental** 增量 | 自上次**任意備份**之後的變更 | 完整備份＋之後必要的增量備份鏈 |

例如：星期日完整備份，週一 A 有修改，週二 B 有修改。
- 週二**差異備份**收錄週一與週二以來的改動。
- 週二**增量備份**只收錄自週一那次備份後的改動。

**Local Backup**：備份與原資料放在同一地點；**Off-site / Remote Backup**：不同地點，降低同一災害同時毀損原資料與備份的機率。（第 34 頁）

**異地備援**重點是異地設備與資料同步，使災害時可以恢復服務；不等於只存一份異地備份。（第 35–36 頁）

## 廢棄媒體（第 38 頁）

儲存敏感資料的紙張、磁性媒體、快閃儲存裝置在報廢時需要安全清除或合適的實體銷毀。**不要將原始資料舊例的「拿鐵鎚砸隨身碟」直接當成組織銷毀程序**，實務需考慮安全、可驗證性與媒體類型。

## 適用性與限制

本研究整理資訊安全基本概念，具體安全控制必須依資產、威脅模型及系統環境驗證。不能將歷史範例直接視作目前的上線安全標準；比較見 [現行技術指引差異](security-guidance-evidence-review.md)。
