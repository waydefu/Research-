研究日期：2026-11-11（Asia/Taipei）  
研究狀態：四部使用者提供的影片已完成 FFmpeg 解碼與逐幀灰階差異統計；視覺以抽樣分鏡為主。未取得 R16 發行 ZIP 六部影片；未在 Android 裝置改系統檔。

總解碼影格 **18,547**。其中開機動畫教學容器的 `ffprobe` 幀數約為 8,916，但本次 FFmpeg 輸出 8,917 張，故以實際 decode count 為準。手機影片為 VFR，不能由固定平均 FPS/影格序號推算精準時間戳，應採 PTS 分析。

本次使用縮至 96×54 或相近尺寸的灰階畫格做均值亮度、低亮度比例及相鄰幀平均絕對差（MAE），**只用於偵測大畫面轉場，不能評分全解析度材質、清晰度或畫面品質**。抽樣分鏡人工觀察≠每幀人工檢視。

## AOSP bootanimation 的實際技術路線

[Android Open Source Project 格式說明](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/cmds/bootanimation/FORMAT.md) 定義影格／part 及 `desc.txt` 的動畫格式。經典格式常由 ZIP 封裝圖像序列與播放定義，與瀏覽器 DOM、JavaScript Canvas 或 Windows WPF 程式碼**並不相容**；是否有裝置廠另外擴充格式，須依當期裝置實作確認。教學示例的 `1080 1920 25` 不可直接照搬至另一型號。

針對 POCO F8 Ultra／HyperOS 的風險：分區保護、Verified Boot、解鎖／root、OTA、開機循環與救援方法均需事先確認。沒有實機系統版本、文件與備援鏡像，就不應直接修改 `/system/media` 或宣稱已能替換。

## 可重現的下一輪測試（未執行）

1. 保留樣本 SHA、codec、時間基與 per-frame PTS；執行 ffprobe 和 FFmpeg 解碼，核對容器影格計數與實際 decode discrepancy。
2. 對照 Intro/Idle/Finale 三段影片首尾：構圖、眼部姿態、亮度、色域、畫格時間間隔與解碼器切換延遲。
3. 將自製且有權利的視覺素材匯出為 Android 支援的 PNG 序列，先以離線預覽器檢查裁切、環圈轉場、字體可讀性與重複區段，再評估系統移植。
4. 以非破壞性的手機預覽測 FPS、耗電、熱降頻、動畫完整性及視覺閃爍；確認原廠 recovery 和回退方案後才評估系統層操作。

**成果不包含**任何實機跑分、root 操作、系統分區變動或第三方視覺素材再散布。
