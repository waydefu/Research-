## 1. IT、系統與資訊

- **Information Technology（IT）**：結合硬體、軟體及服務來管理、傳遞和分享資訊。（PDF 第 2 頁）
- **Systems Analysis and Design**：循步驟開發高品質資訊系統的方法。（第 3 頁）
- **System**：互相關聯的組成部分共同產生特定結果。（第 4 頁）
- **Mission-critical System**：對企業日常運作至關重要的系統。（第 4 頁）
- **Data**：系統的原始事實；**Information**：將資料轉化後，能對使用者產生價值的資訊。（第 4 頁）

### 資訊系統五要素

| 要素 | 說明 |
| --- | --- |
| Hardware | 實體硬體設備 |
| Software | 控制硬體並產生資訊的程式；含 OS、驅動與安全工具等系統軟體 |
| Data | 原始資料 |
| Processes | 使用者、管理者和 IT 員工執行的工作／業務流程 |
| People | 參與或關心系統的人員，包含 **Stakeholders（利害關係人）** |

出處：PDF 第 5–7 頁，圖 1-4。

## 2. 網路商業與流程建模

- **B2C**：企業對消費者，例如在線上比較商品與完成購買。
- **B2B**：企業對企業，例如供應商取得價格或庫存資訊。
- **C2C**：消費者對消費者，例如二手衣買賣。
- **SCM（Supply Chain Management）**：供應鏈管理。
- **Business Profile**：企業使命、功能、組織、客戶、競爭者等概況。
- **Business Process**：可描述和記錄的一組交易、事件和結果。
- **BPM**：業務流程圖形化；**BPMN** 是表示事件、流程、工作流的標準化符號。

出處：PDF 第 9–14 頁。

## 3. 商業資訊系統

| 名詞 | 用途 |
| --- | --- |
| Enterprise Computing | 支援整個公司的營運及資料管理 |
| ERP（Enterprise Resource Planning） | 企業資源規劃 |
| TP（Transaction Processing） | 處理每日交易產生的資料 |
| Business Support Systems | 支援不同職級的工作資訊需求 |
| Knowledge Management | 以知識庫提供查詢與知識使用 |
| User Productivity / Groupware | 信件、試算表、共同作業、團隊協作 |
| Digital Assistants | 結合知識管理、生產力系統與 AI |
| Systems Integration | 將不同系統能力整合 |

企業組織層級概念：高階主管做長期策略、中階主管協調資源與方向、監督者管理日常工作、第一線員工使用交易處理系統；知識工作者包括分析師與程式設計師等。（PDF 第 15–23 頁）

## 4. SDLC 五階段（重點）

| 階段 | 課本主要產出／任務 | PDF |
| --- | --- | --- |
| Systems Planning | 接收正式 Systems Request、進行 Preliminary Investigation | 第 24–26 頁 |
| Systems Analysis | 建立新系統的 **Logical Model** | 第 26 頁 |
| Systems Design | 建立滿足需求的 **Physical Model** | 第 26 頁 |
| Systems Implementation | 建置新系統 | 第 27 頁 |
| Systems Operations | 系統交付使用、維護、改善、保護 | 第 27 頁 |

**辨別：Analysis 重在需求與邏輯模型；Design 重在實體模型。**

## 5. 開發方法與工具

- **Structured Analysis**：以 SDLC 分階段規劃、分析、設計、實作及支援資訊系統。
- **Object-Oriented Analysis**：把資料和操作資料的程序組合成物件。
- **Agile Methods**：循漸進原型與多輪使用者回饋調整系統；教材提醒可能存在文件不足、責任模糊及忽略整體商業視野等風險。
- **Prototype**：資訊系統早期可運作版本，用於測試概念、輸入／輸出與介面。
- **ALM、IDE、CASE**：教材列出的開發支援工具類型。

出處：PDF 第 24–31 頁。

## 6. IT 部門與系統分析師

IT 部門常見職能：應用程式開發、系統支援及安全、使用者支援、資料庫管理、網路管理、Web 支援與 QA。（第 32–34 頁）

**Systems Analyst（系統分析師）**：分析與設計系統，也需要理解業務、聆聽使用者、協調管理者與程式設計師、取得回饋並運用批判性思考。（第 35–40 頁）
