## 先做：已授權的內容與圖片兩包

### W1｜逐篇導讀（獨立 PR）
- 針對現有 87 份公開 Markdown 建立一對一的繁中編輯導讀：**這是什麼／能做什麼／讀前限制**，約 60–160 字（來源索引和模板允許較短），以原文可核對的內容為準。
- 顯示標題與主題取自已合併 PR #40 的 `research-taxonomy.mjs`；不以舊 `CURATED` 標題／分類覆蓋，舊作者及外站 demo 不消失。
- 原文 Markdown、H1、SHA、文章路由、Pagefind、反向連結、外站限制不變。
- 明確區別人工編輯的導讀、原文內容概覽與尚未驗證的外部主張；有爭議的數字／作者／測試沒有來源不自行補寫。
- Gate：逐篇導讀覆蓋率、繁中與空字串檢查、舊讀者入口／搜尋／無 JS／行動版與 E2E。

### W2｜逐篇圖片與素材治理（另一獨立 PR）
- 每篇研究頁與典藏清單使用**對應研究主題的專屬視覺**，不再把同一領域共用 SVG 當成不同文章的專屬素材；可採原創、可重現且不含第三方商標的**資訊圖／示意圖**，不冒充原作品截圖。
- 素材登錄至少包含來源路徑、圖片型態（原創示意／已授權來源／暫無）、對應研究、alt、授權和查核限制。未知第三方授權不推定可用，也不直接複製他站圖片。
- 原創示意需與內文主題有可解釋的關聯；優先做到每篇有不同素材，兼顧手機載入、適當尺寸與 reduced-motion。
- Gate：87 篇精確映射、不存在圖片 404／重複誤標、圖片來源資料可核、無字型授權風險；建置、連結、Pagefind 和 E2E。

## 再回來做：W3｜Repo Map + AGENTS + 新鮮度（獨立 PR）

**目的：讓後續 Coding Agent 能在低上下文成本下找到「去哪讀、改哪裡、怎樣驗」。**

1. **Repo Map**：先盤點現有 `AGENTS.md`、`site/AGENTS.md`、`site/HANDOFF-CURRENT.md`、`site/src/lib/catalog.mjs`、網站頁面與腳本；在 `site/` 建導航圖，標明檔案作用、讀寫界線、資料流、測試、誰會受到修改影響。導覽由現有 tracked paths 對照，不臆測執行期呼叫圖。
2. **AGENTS 導航**：保持根規範極簡與原有授權；分層指引只提供「何時讀哪個文件」連結，不將歷史交接快照冒充即時狀態。任何根目錄 `AGENTS.md`、`.github/`、RuleSet、workflow 變更要先確認 Owner 對**具體檔案**的授權。
3. **可驗證 freshness**：檢查導航中明列的必需路徑存在、過時 main SHA／歷史 PR 狀態不可被標為當前，產生清楚錯誤；成本較低的 Node 內建 test 優先，避免新增 MCP／依賴／向量資料庫。
4. **模型上下文最小化**：先讀入口（任務分流）→ 定位子系統 → 讀 1–3 份必需原始資料 → 必要時再全文搜，避免把 87 篇研究或所有工具 schema 一次載入。
5. Gate：導航路徑／來源索引與 HEAD 一致、破壞一個檔案可檢測、無需擴大權限、所有現有站點 CI 不回退。

## 授權及交付界線

- 三包都先在 **`site/` 內**完成，不先觸及 `research/`、`docs/`、`showcase/` 原文。
- 原始研究唯讀；不修改 workflow／Ruleset、不得藉由文字指示啟動 MCP、不合併、不部署、不啟動 P2。
- 每個 PR 寫明當前 HEAD、實際 PASS 的三種 CI（Research integrity、V3 P0、Publish Pages 的**驗證 job**）、未量測的真機／效能，以及 Owner 待確認項。
- 「圖片已分配」不等於「圖片已人工美術驗收」，「CI PASS」不等於 G0 實機／美術定案。
