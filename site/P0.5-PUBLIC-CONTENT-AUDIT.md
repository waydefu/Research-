# P0.5｜公開研究通用化：全量盤點與第一批技術正文

更新：2026-11-04（Asia/Taipei），基線為合併 PR #47 後 `main bd3aac85e5ee`。

## 目標與證據界線

公開網站服務一般讀者。當研究原始 Markdown 帶有過期的專案計畫、Agent 工作指令、PR／CI 快照時，不應把這些紀錄直接當作不依賴脈絡的技術知識。

本包保留原始研究完整性，另建**公開技術正文**。正文是依原文整理的技術方法，並非重新實測或逐項獨立驗證外部主張。

## 87 篇全量初篩

`cd site && npm run audit:public` 會依當前 `allDocs()` 對所有公開 Markdown **逐篇**輸出：來源檔案、文字訊號風險、是否已有通用技術正文。`npm run audit:public -- --summary` 看分類總數，`npm run audit:public -- --json` 可供自動處理。

檢查會辨識具體專案名稱、Owner／本專案說法、歷史 PR、P0／P1／V2／V3、交接與工作包等措辭，並分成「優先整理／人工核對／一般內容候選」。**這是機械式風險線索，不是 87 篇全都逐段人工查證，也不是證明低風險文章已達可出版品質。** README、SOURCES 和模板仍然列入盤點，不假裝它們都是完整的技術文章。

## 程式與驗收

- `npm run check`：87 篇分類與來源對應、4 篇編輯內容、人類可讀的前台與原始 HTML 檔案共存。
- `npm run build`／`npm run provenance`：產生所有原始文章網址與 Pagefind，不遺失 git SHA。
- `npm run e2e`：4 篇手機版正文、來源可展開、無 JS 可閱讀、未編輯的文章功能不回歸。
- 這些檢查不等於完整外部事實驗證、美術／裝置效能或作者授權的獨立法律審查。

## 後續分批原則

先檢查全量掃描結果的優先項，再逐篇對照原始來源、核對技術結論與不確定性，擬定公開可讀的新正文。避免將內部實作規劃寫成普遍事實，亦不應刪掉原始來源證據。每批先以 Draft PR 提交，由 Owner 審核後才可能合併／部署。

本包只改 `site/`，不修改原始 `research/`、`docs/`、`showcase/`、GitHub Actions、Ruleset 或正式 Pages。
