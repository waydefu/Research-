## 已驗證現況

- 內容來源：`site/src/lib/catalog.mjs` 直接讀取 `research/`、公開治理及設計 Markdown；靜態 URL、原文、git SHA/date 和引用連結由既有流程提供，不複製或改寫原始研究。
- 人工編輯：`site/src/lib/research-metadata.mjs` 的 `CURATED` 有 **7 筆**，使用 `title/lead/topic/creator/demos`；未在 CURATED 的文章由正規表示式及原文摘要回退。
- 分類與配圖：來源資料夾決定 `group/domain`，`TOPIC_RULES` / `TAG_RULES` 建立細分分類；`site/src/lib/exhibit-info.mjs` 目前提供**領域／細分類圖片**，不是逐篇專屬圖片。
- 書目與溯源：`creator` 與 `demos` 已可人工標示，原始 Markdown 的外部連結可列出；尚無全文章明確的 license、verifiedAt、evidenceLevel、originalSource、image 欄位。
- PR #37 HEAD 的 V3/Pages 回歸顯示當時 **86 篇**來源文件；這是該 SHA 的快照，不是宣稱目前所有 Metadata 都經人工查證。

## 本 PR 的最小實作（不做資料大遷移）

1. `site/src/lib/metadata-schema.mjs`：定義 12 個正式資料欄位 `publicTitle, summary, domain, topic, tags, creator, originalSource, demo, license, verifiedAt, image, evidenceLevel` 與 `schemaVersion: 1`；未知資訊使用 **null**，不捏造作者、授權、查證日或圖片。
2. 舊版 `CURATED` 仍可用原格式；啟動時驗證既有手工覆寫，**任何非法 HTTPS URL、空字串與不受支援欄位會使測試失敗**。
3. v1 元資料可明確區分已查證與未查證、原作品與 demo；仍以既有來源路徑作正式 route 的 group，不允許 v1 的 domain 靜默修改路由。
4. `site/tests/metadata-schema.test.mjs` 用 Node 內建測試驗證舊紀錄相容、完整 v1、缺欄位、無證據卻標已查證、不安全網址及無效圖片；不加新依賴。
5. 保留 fallback，**暫不強制 86 篇歷史文件補齊**，亦不修改 `research/`、`docs/`、`showcase/`、Pages／workflow／Ruleset／iframe 名單。

## 驗證方式與 Gate

- 本地：`cd site && npm ci --no-audit --no-fund && npm run check && npm run build && npm run provenance && npm run e2e`。
- PR CI：要求 Research integrity、V3 P0、Publish Research Showcase 在**最新 HEAD** 真正回報；確認三者經驗證，而非引用前一個 PR 的成功。
- 回歸：研究總數、全文、原文 SHA、Pagefind 中文搜尋、父／子分類、手機 360/768 px、無 JS、外站 demo 只在點擊後載入。
- 目前**未執行真機 Android / iOS、FPS、GPU／熱負載、Owner 美術簽核**，不能標示 G0 PASS。
