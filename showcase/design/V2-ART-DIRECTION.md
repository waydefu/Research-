# V2 ART DIRECTION — THE OBSERVATORY / EVIDENCE ENGINE

**Edition** 2026-11-02 · **Status** Proposed art direction / not implemented · **Owner review** Required before V2 implementation

> **品牌命題：**「從未知到可驗證。」／**From the unknown, into evidence.**
>
> **視覺中心：** 一座不屬於任何現有動漫或數位工作室作品的 **Evidence Engine｜光譜觀測核心**。它不是賽博祭壇、宇宙神明或「科技萬花筒」，而是把**發現、比對、驗證、追溯**變成可互動的儀器。
>
> **美術口令：** Dark matter / gilded evidence / cyan inference / controlled revelation.
>
> **核心否決規則：** 任何光效如果無助於方向感、內容探索、狀態理解或節奏塑造，就應先刪掉。

## 1. 一眼辨識的品牌原型

原始圖形的輪廓：**偏心雙軌金屬環 + 中央不對稱菱透鏡 + 外側刻度弧 + 少數可追蹤證據軌跡**。從遠距觀看，像一座精密而有古典天文儀感的未來觀測機，而不是標準發光 HUD 圓圈。

- **核心外型不可採用：** 動畫截圖中的中央完整菱形 Logo、原字樣、角色、密集環形英文裝飾；Active Theory 的任何線條語言與作品布景；大量無規則的霓虹粒子。
- **獨創構成：** A 軌道是偏心斷環，B 軌道有非均勻刻度與緩慢的平面傾角，C 層是具檔案節點位置的穿透平面；中心是一個斜切菱透鏡（不是完整徽章）。
- **材質：** 非鏡面純金。主體用深色氧化鈦／香檳金邊緣／磨砂陶瓷；金色是**被定向光照亮的加工邊緣**，不是「填滿整個物體」。
- **光照：** 一道暖金主光、一個極低強度青藍輪廓光、深色負補光保留陰影；當場景「解鎖來源」時只讓中心數百毫秒提高明度。
- **空間：** 背景有可參照的星象／測量網格，但只靠兩三種視差層；沒有全頁廉價點點雨。

## 2. 配色方案｜CELESTIAL INTELLIGENCE（設計候選，不是原動畫色碼）

取自使用者三張圖的光色關係，經人工調整以達到文字對比與材質辨識。以下色碼不是從動畫官方素材得到的原始值。

| Token | HEX | 視覺角色／比例設計 |
| --- | --- | --- |
| `space.0` | `#0A101D` | 黑藍主舞台，約占首屏大面積 |
| `space.1` | `#101B2B` | 背景縱深和側翼容器 |
| `space.2` | `#142D40` | 星圖區／細節工作臺；不是大量圓角卡片 |
| `cyan.deep` | `#167B90` | 圖線／測量刻度；**禁止用於深底的小字** |
| `cyan.plasma` | `#40D4DE` | 互動焦點、尚在探索的追索路徑 |
| `gold.primary` | `#E4B451` | 確認聚焦、金屬物件亮邊、關鍵按鈕；**不代表研究已驗證** |
| `gold.soft` | `#F8E8BD` | 局部柔光、可讀的強調文字 |
| `text.primary` | `#F5F3EA` | 主要正文和標題 |
| `text.muted` | `#A9C2CB` | 次要正文；正式實作須量測每個使用背景 |
| `white.energy` | `#FFFFFF` | 極小面積峰值；不可閃屏 |

**建議亮度治理（美術政策，不是已量測統計）：** 暗部約 70–80% 視域、金／青光源區約 15–25%，近白亮斑保持極少區域（例如單一核心小於 2% 的 Hero 面積）；整頁不可滿屏 Bloom。

**對比的理論計算（標準 sRGB，非半透明場景實測）：**
- `gold.primary` / `space.0` 約 9.91:1；/ `space.2` 約 7.40:1。
- `cyan.plasma` / `space.0` 約 10.58:1；/ `space.2` 約 7.90:1。
- `text.primary` / `space.0` 約 17.10:1；/ `space.2` 約 12.77:1。
- 深青 `cyan.deep` / `space.0` 約 3.87:1，**不適合當一般小字**；它只是圖層色或大尺寸符號候選。
- 文字落在 gradient / bloom / 透明遮罩上時需按**最差實際背景**重新測量，不能沿用上述實心色的比值。

### 2.1 色彩的「語義」而不是裝飾

| 認知場景 | 色彩／行為 | 要傳達的事情 |
| --- | --- | --- |
| 未知 | 宇宙黑 + 低照度青藍軌跡 | 有線索但尚未得出結論 |
| 探索 | 電漿青游標回應 + 少量開啟的刻度 | 訪客正在選研究主題 |
| 比對 | 冷暖雙軌稍微分離／重新對齊 | 正比較來源／說法／假設 |
| 聚焦 | 香檳金照亮單一檔案的索引路徑 | 有具體文件可以閱讀，**不是驗證通過標章** |
| 失敗／未知 | 保持同等對比與文案註記，不使用貶義暗紅光 | `Unknown` 必須以文字說明，不能只靠色彩推斷 |

## 3. Typography｜「天文儀 × 技術研究」而非動漫標題

- **Display 英文：** 具有刻度或科學儀器氣質的高對比 serif / 變體字，**搭配**較中性的現代 grotesk；不強制使用付費字體。首頁保留約一處大字主標，避免每一節都用誇張展示字。
- **中文：** 可清晰閱讀的繁體中文黑體／明體混搭；展示書法式筆畫只用於極短標題，不能犧牲資訊密度。
- **數字與標籤：** 等寬系統字、01/04 敘事編號、來源 SHA、日期與量測狀態；附字距，避免小到手機上不可讀。
- **建議字級範圍：** Desktop Display 80–164px（依版寬調整）；Mobile Display 44–70px；正文 Desktop 16–19px／Mobile 16px 以上；Micro labels 原則上不低於 12px（需真機檢查）。
- **禁止：** 為了模仿動畫把金色文字繞完整圓周導致難讀、所有內容都塞等寬小字、字幕式擠壓文字、SVG 取代所有正文。

## 4. 首頁導演故事板（文字視覺稿，尚無渲染）

### SCENE 00 — FIRST SIGNAL｜第一束訊號

**畫面：** 先呈現乾淨的 DOM 站名和一句命題。暗藍背景中只有極細的青色刻度，一道金線慢慢完成缺失的曲線；沒有漫長品牌 Loading Screen。

**視覺動作：** 首次可互動狀態優先，核心裝置在內容出現後再漸進初始化。背景不准遮蓋首屏 CTA。建議單次柔和進入動作 450–900ms（**創意預設，非性能測試值**），減少動效則直接顯示。

**主標提案：**
> THE UNKNOWN, ENGINEERED.
> 讓每一個未知，都有可追索的證據。

**CTA：** 「探索研究」明確直接跳到 Research Explorer；次要「觀察核心」才進入可玩場景。沒有強制 intro。

### SCENE 01 — THE EVIDENCE ENGINE｜觀測核心

**畫面：** 深色背景帶精確光照的偏心金屬環體；中心是一枚小型菱透鏡；只有一條冷色曲線顯示「當前追索方向」。

**動作因果：** 指向不同研究領域時，環體的**相對方位**（而非瞎轉）切換至相應的區域；一側浮出**真正從 Markdown index 建立的**標題與可點擊文章入口。點選後同步更新 Explorer 分類，並提供來源可見的文件。

**可讀性：** 中央雕塑不蓋住文字；聚焦讀取狀態時主體停止動作；任意時刻皆可選 `Open research index`。

### SCENE 02 — SPECTRAL ATLAS｜光譜研究圖

**畫面：** 不是 60 張卡片，而是六個研究星域的**層級式導航**。星域採較低亮度的空間弧；實際文獻用可見的原始檔名、分類及數量呈現。

**操作：** 游標／觸控／鍵盤點亮一個領域 → 右側（手機為下方）出現真實 Markdown 文件列表。若某資料缺 evidence-level metadata，只顯示「未標記」，不能憑視覺計算虛假分數。

**性能：** 可只用 SVG + DOM 搭配一個場景 shader；不需要每個節點都有一個 WebGL canvas。

### SCENE 03 — THE PROTOCOL｜驗證儀式

**畫面：** 主核心拆成四個清楚的線性階段：SOURCE → QUESTION → TEST → GOVERN。各階段的光由青藍轉暖金，但不是「黃色 = 已驗證」。

**操作：** 每一步可點開原始治理與研究文件；未完成的 EAG-100 仍顯示「自訂研究標準／未通過完整驗收」。**不要把 100 或 20/5 當成已合格分數。**

### SCENE 04 — THE DOSSIERS｜實用研究瀏覽

**畫面：** 由圓形／空間逐步過渡到可掃描、高密度的編輯式資料列表。意圖是**讓觀眾從感性探索返回精確文件查找**。

**功能：** 搜尋標題、章節、關鍵字、領域、來源檔案；直接開 GitHub 原文；無結果、載入失敗、無 JS、鍵盤、手機皆有 fallback。不因 WebGL 場景結束而刪掉搜尋狀態。

### SCENE 05 — BACK TO SOURCE｜返還原文

**畫面：** 光路緩慢收束回單一來源路徑；結尾只保留 1–2 個足夠醒目的行動入口：原始碼／研究庫。不要再塞一整屏花俏特效。

**動作：** 轉場可以取消或直接跳過；單獨顯示此章仍必須是完整優美構圖。

## 5. Responsive Layout：不是縮小版

### Desktop（約 ≥ 1100 CSS px）

```text
┌──────────────────────────────────────────────────────────────────┐
│ R / RESEARCH                         EXPLORE  METHOD  SOURCE   │
│ 01 / OBSERVATORY                                            01 │
│                                                                  │
│  THE UNKNOWN,                 ◌───[  GOLD / CYAN  ]──◌           │
│  ENGINEERED.                    evidence engine                  │
│  認知命題                        context / focus                 │
│  [探索研究] [觀察核心]            (non-blocking GPU layer)        │
│                                                                  │
│  RESEARCH INDEX ›              SVG source-linked domain markers │
└──────────────────────────────────────────────────────────────────┘
```

桌面寬度不是讓主標與雕塑彼此競爭。建議按需使用 10/12 欄 flexible grid；核心最多佔可用主要版面約一半，實際依文字長度與裝置比例微調。背景光不能照到正文的底層。

### Mobile（約 320–430 CSS px）

```text
┌─────────────────────────┐
│ R/          MENU        │
│ 01 / FIRST SIGNAL       │
│                         │
│    mini orbital core    │
│       ◌◇◌               │
│                         │
│ THE UNKNOWN,            │
│ ENGINEERED.             │
│ 從未知，到可驗證。        │
│ [探索研究]               │
│ [觀察核心]               │
│                         │
│ ─── 繼續閱讀 / 索引 ───   │
└─────────────────────────┘
```

- Mobile **重新分鏡**：先讓品牌輪廓有辨識度，再給主文案與明確 CTA；核心通常只保留靜態／低密度慢動作，放在文字背後仍不能壓住可讀性。
- 手機不得強制橫向捲動讀正文，不得要求雙指拖曳；可用一指點選且都有 DOM 等價入口。
- 方向變動、瀏海 safe area、軟鍵盤打開後的搜尋欄皆需測；可以在手機上選擇**完全不使用 WebGL**，若其視覺構圖仍有完成度即為成功。
- Mobile 開場不要先載大 GPU 資產再允許搜尋。

## 6. Motion Principles｜品質靠節奏不是幀數

| Motion | 場景 | 設計意圖 | 建議上限（設計候選） |
| --- | --- | --- | --- |
| Core alignment | 選擇研究主題 | 清楚暗示從 A 路徑轉至 B | 500–800ms，支援立即跳至末態 |
| Edge illumination | 研究節點進入焦點 | 表示當前 focus，而不是評分 | 150–250ms |
| Field transition | 星域變換 | 給空間關係，不重置 scroll | 350–650ms |
| Camera parallax | desktop fine-pointer | 增加少量深度 | 位移控制在非常低的可讀範圍 |
| Dossier entrance | 從視覺切到清單 | 讓資訊優先 | 200–400ms |
| Reduced motion | OS 選擇減少動態 | 保留所有資訊 | 無視差、縮放、無限旋轉；以靜止／淡入代替 |

以上時間範圍是**設計參數**，不是已經在 Safari／Android 測得的流暢度結果。不得為了符合動畫節奏做 scroll-jacking 或阻擋焦點移動。

## 7. High-fidelity 設計交付包（實作前應審查）

必須產出：
1. **12 張關鍵畫面狀態**：Desktop/Mobile × Hero(Default、focus、reduced motion) + Explorer(Default、loading、failure) 的選定矩陣，總計明確標註不夠的狀態須補齊。
2. **5 秒首屏辨識測試**：訪客能說出這是研究／工程資料庫，並在可見的路徑進入研究；5 秒只是擬議的實測任務，不是既有結果。
3. **一個原創核心輪廓**的三個視角與黑白靜止版，去掉 bloom、粒子、雜訊仍要有辨識度。
4. **真正對應資料來源的 state diagram**：category / query / selectedDocument / evidenceStatus（可選且需要來源）→ renderer state；未有的資料要顯示 `Unknown`。
5. **字體與排版測試**：長標題、中文換行、手機最窄寬、不同語系、非拉丁文和 200% zoom。
6. **色彩／材質校對**：實心對比+實際最差漸層對比、黑白／色覺異常模擬。
7. **反模板檢查**：禁止所有區塊通用圓角卡、重複 Glow、無資訊目的的粒子、全站不斷捲動 pin。
8. **法務風險**：只借用「金色環與青色光」等抽象語言，所有 logo、3D 幾何、裝飾性 glyph、微文案必須原創或確認授權。

## 8. Creative Director 拒絕門檻

- 只換成青藍金色、主體外型與互動不變 → **Reject**。
- Hero 可以很炫，但沒有 DOM 可用索引 → **Reject**。
- 為了像動畫截圖而抄了原菱形徽章、環形字樣或角色 → **Reject**。
- 首屏所有元素同時轉、發光、移位 → **Reject**。
- Mobile 的「關閉 WebGL」只剩一大片空黑底 → **Reject**。
- 色彩依據任意「科學可信度」變色而沒有來源 schema → **Reject**。
- 反之，如果靜態版面足夠鮮明、研究連結清楚、只用一項實時核心視覺也能完成體驗 → **可以通過概念審查**。
